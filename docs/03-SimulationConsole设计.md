# 03 · Simulation Console 设计

> 状态：已生效（2026-09-30）
> 上游：[02 模拟核心与数据架构](./02-模拟核心与数据架构.md)（Clock / 事件流 / 存档 / 确定性）
> 定位：**P0 开发工具**。没有它，开花（7 天）、老桩（数月）这类核心内容无法开发与验证。

---

## 1. 目标与非目标

**目标**

* 让"时间跨度 > 开发周期"的内容可测试：加速、跳转、重放
* 让"期待系统"可观察：事件流、SignalStrength、预算状态
* 让"程序化审美"可批量检验：100 株 / 500 株、唯一性指标
* 让"小尺寸可感知"（R5）可随时验证
* 为异常路径提供注入器：时钟回拨、巨量离线、损坏存档

**非目标**

* 不进发布包（构建开关隔离，生产构建零代码、零体积）
* 不做通用调试器；只服务本产品的模拟域
* 不修改模拟语义——Console 的一切动作都必须走 02 定义的正规入口

---

## 2. 启用与隔离

* 仅在 `import.meta.env.DEV` 构建（或显式 `--dev` 启动参数）中注册
* 快捷键呼出 / 收起面板（DOM overlay，不进 three 场景）
* Console 的时间操作**只改变 simTime 推进，不注入 InputEvent** ⇒ 重放与正式存档天然一致；操作会置 `dev.tainted` 标记（仅提示用）
* 发布构建验收：grep 不到任何 `dev/` 代码

---

## 3. 时间控制

| 控件 | 行为 |
| --- | --- |
| timeScale | ×1 / ×10 / ×100 / ×1000 / 自定义（对数滑条） |
| Advance | +1h / +6h / +1d / +7d / +30d / +1y |
| Jump | 跳到下一事件 / 指定模拟日 / 指定日期 |
| 流控制 | 暂停 / 恢复 / 单步（1 模拟小时） |

实现约束：全部调用 `SimulationClock.advance()`（02 §1），与启动 catch-up 走**同一条批量管线**——这本身就是对批量模拟的持续测试。

---

## 4. 重放与时间轴（R13）

### 4.1 原理

不做真回退。利用 I1 确定性：

```text
seek(day N) = 从 seed + 出生状态重放 InputTimeline 至第 N 天
            + 每 7 模拟日一个状态检查点（缓存）加速
```

### 4.2 UI

* 时间轴滑条（Day 1 → 今天），拖动 = seek
* 播放 / 暂停 / 速度（×1 模拟日每秒起）
* 事件标记刻度：major = 菱形、growth = 圆点、micro = 隐去
* 用途：**验证"酝酿感"**——观察者应能在迹象生命周期的相邻几天之间察觉 SignalStrength 爬升（对应 04 §7 曲线）

---

## 5. 事件检查器

* 实时事件列表：seq / simTime / kind / tier / signalStrength
* **预算仪表盘**：三层事件的本日计数 vs 配额、冷却剩余、排队深度（02 §2.4）
* **强制触发**：对某事件把条件权重与概率临时置 1——必须走正常管线（迹象与酝酿照常发生），禁止特例直生成
* 过滤与搜索：按 tier / kind / plantId

---

## 6. 状态检查器

* WorldState 树形检视：水分、应激累积器、stretch、季节相位
* 叶片表：每叶 ring / maturity / turgor / colorState / damage，支持按 ring 着色
* **Phenotype Diff**：选两个时间点（如 Day 30 vs Day 90）并排对比 Snapshot 参数变化——直接回答"这段时间到底变了什么"

---

## 7. 批量与唯一性工具

* Generate N（100 / 500）：从随机 seed 批量生成，网格排布渲染
* 一键导出 contact sheet PNG（总方案 §41.4 的自动化形态）
* **数值唯一性指标**（R14，M5）：叶数 / 高宽比 / 紧凑度 / 主色相直方图 / 分枝数；计算两两距离，报告最近邻 top-20——回答"是真自由，还是 5 个模板换参数"

---

## 8. 小尺寸可感知工具（R5）

* 同一植物同步渲染 80 / 100 / 140 / 180 px 缩略图 + 当前窗口实际尺寸
* 迹象检查单：对每个 lifecycle 阶段列出 SignalStrength，标红"在 100 px 下不可辨"的阶段
* 验收规则：进入 M3 / M4 验收前，所有计划内迹象必须在 100 px 缩略图可辨认

---

## 9. 存档与异常注入器

* 存档导出 / 导入 / 快照对比
* 时钟异常注入：回拨 1h / 回拨 1 天 / 回拨 30 天 / 前跳 90 天 / DST 假象
* 损坏存档模拟：截断 / 字段缺失 / 版本超前——验证 02 §6.2 回退逻辑
* 事件日志查看器：原始 JSONL 浏览

---

## 10. 发现率日志（R15）

* 事件落盘时附加 `visible`（渲染时长 > 阈值）；运行期统计 `discovered`（指针在事件区域停留 / 缩放 / 点击邻近）
* 输出本地 JSONL：`Triggered / Visible / Discovered` 三计数
* 只回答一个问题：**"是发生太多没人看，还是根本没发生"**——不联网、不上报

## 12. 验收

* ×1000 加速连续跑 1 模拟年：无崩溃、RAM 稳定、事件流完整
* seek 随机 20 个时间点：状态与连续推进一致（确定性自检）
* 强制触发开花：迹象按 SignalStrength 曲线逐步出现，而非瞬间弹出
* 发布构建中 grep 不到任何 dev/ 代码
