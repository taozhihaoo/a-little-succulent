## 3. 验证项

### 主线（Floating Mode）

| # | 项 | 方法 | 通过标准 |
| --- | --- | --- | --- |
| A1 | 透明无边框窗口 | `transparent + frame:false + alwaysOnTop`；在深 / 浅 / 视频背景上观察 | 无黑底、无闪烁、边缘干净（Win10 1909+ 与 Win11 各测一次） |
| A2 | three.js 透明渲染 | 占位模型 + 透明背景 RAF；**浅色模型压深色 / 深色压浅色背景，放大实测边缘** | alpha 混合正确；浅色内容边缘无白边 / 黑边（透明窗口预乘 alpha 陷阱，缓解：轮廓处避免抗锯齿、提高 DPR、必要时 alpha 锐化后处理）；GPU 加速被禁用时行为已知（记录降级方案） |
| A3 | 鼠标穿透 | `setIgnoreMouseEvents(true, { forward: true })` 动态切换；raycast 代理网格判定命中 | 透明区域点击落到下层应用；植物 / 盆区域可接收事件；指针样式正确 |
| A4 | 拖动 | 按住植物拖动窗口（M0 阶段拖窗口即可）；**实现固定为 IPC 手动移动窗口**（renderer 命中 → main 进程 `setPosition`），禁用 `-webkit-app-region: drag`（与动态 `setIgnoreMouseEvents` 冲突） | 平滑、无残影；释放后位置持久；与穿透动态切换互不干扰 |
| A5 | 置顶与全屏行为 | 覆盖独占全屏游戏 / 无边框窗口 | 行为如实记录（预期：独占全屏时不可见），给出文档级说明 |
| A6 | 托盘 | Tray 菜单：显示 / 隐藏 / 退出；关窗 = 进托盘 | 菜单可用、退出真正销毁进程 |
| A7 | 多显示器 | 跨 1080p / 4K、不同缩放屏移动 | 位置 / 缩放正确，无模糊、无错位 |
| A8 | DPI | 100% / 125% / 150% / 200% | 无双重缩放（统一 zoomFactor 策略）；文字与 3D 同清晰 |
| A9 | 渲染三态雏形 | Idle 停 RAF；指针进入唤醒；微动画短 burst（02 §4） | Idle 态任务管理器 GPU 引擎 ≈ 0%、CPU ≈ 0% |
| A10 | 性能基线 | 启动时间 / Idle CPU / GPU / RAM；1h 与 8h soak（占位模型） | 记录成基线表；RAM 无增长趋势 |
| A11 | 开机自启 & 单实例 | `app.setLoginItemSettings`、`requestSingleInstanceLock` | 生效；二次启动聚焦已有实例 |
| A12 | 休眠 / 唤醒钩子 | powerMonitor suspend / resume 接入日志 | 唤醒后能拿到可靠时间增量（为 02 §1.4 铺路） |
| A13 | 全屏应用检测 | Electron 无内置 API；spike 两条路线：`SHQueryUserNotificationState`（N-API 原生模块）与"前台窗口矩形 vs 显示器矩形"对比；含 electron-rebuild 打包验证 | 得到可用方案；原生依赖能随 electron-builder 正常打包；失败则记录降级方案（降频轮询 / 暂时砍掉该优化，见 02 §4） |

```text
连续推进 = 分片推进 = 从种子重放    （状态与事件流逐字节一致）
分片变体：advance(10d) == advance(5d)+advance(5d) == advance(1h)×240
存档续跑：Day10 存档 → 载入推至 Day20 == Day0 直推 Day20

```

## 4. 项目骨架

```text
tech：Electron（当前稳定版）+ Vite + TypeScript(strict) + three
结构：packages/sim | packages/render | apps/desktop（完整定义见《07 代码架构》）
约束：main / preload / renderer 进程边界从第一天成立；contextBridge 受控 IPC；类型化 IPC 注册表
门禁：sim 包 tsconfig types:[] + 运行时依赖白名单 + CI import graph（sim ↛ render/electron/DOM）
脚本：dev / build / typecheck / lint / test（Vitest）
打包：electron-builder 配置占位即可（M7 才是重点）
```

## 5. 性能测量方法

* CPU / RAM：Process Explorer 采样（Task Manager 交叉核对）；GPU：任务管理器 GPU 引擎按进程读数
* soak：8h 挂机脚本（定期截图 + 内存采样到 CSV）
* 所有数字写入 `docs/M0-验证记录.md`，作为后续里程碑的对照基线（02 §7 预算表的实证起点）

## 7. 风险与预案

| 风险 | 预案 |
| --- | --- |
| 透明窗口在某些 GPU / 驱动下渲染异常 | 记录复现条件；降级链：禁用硬件加速 → 不透明窗口模式（体验降级但可用） |
| 独占全屏无法置顶 | 如实文档化（行业普遍限制）；目标场景改为无边框窗口游戏 |
| 穿透 forward 在个别系统失效 | 兜底：植物外接矩形判定 + 手动开关 |
| `-webkit-app-region: drag` 与鼠标穿透冲突 | 已规避：拖动固定走 IPC 手动移动（A4），不使用 CSS drag region |
| 透明窗口预乘 alpha 边缘白边 / 黑边 | A2 实测确认；缓解：轮廓处避免抗锯齿、提高 DPR、必要时 alpha 锐化后处理 |
| Electron 版本 API 变动 | 锁定稳定线，升级放入 M7 检查单 |
