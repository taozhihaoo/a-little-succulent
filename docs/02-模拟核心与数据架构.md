## 0. 设计不变量

以下六条是整个系统的宪法条款，任何实现改动都不得违反：

| # | 不变量 | 来源 |
| --- | --- | --- |
| I1 | **确定性**：相同 Seed + 相同输入序列 + 相同 simulationVersion ⇒ 相同状态与事件流 | 总方案 §50 |
| I2 | **模拟与渲染严格分离**：`sim/` 目录禁止 import three.js 与 electron | 总方案 §49 |
| I3 | **时间单调**：SimulationTime 只前进，绝不倒退 | R3 / R4 |
| I4 | **无逐秒 tick**：一切模拟 = `simulate(state, inputs, t0, t1)` 批量结算 | R2 |
| I5 | **存档是状态不是几何**：不保存任何渲染产物 | 总方案 §51 |
| I6 | **版本钉扎**：旧存档永远按其 simulationVersion 解释，禁止隐式重算 | 总方案 §33 |

## 1. 时间模型

### 1.1 两个时钟

```ts
interface Clock {
  simTime: number;      // 虚拟毫秒，单调递增，随存档持久化
  lastWallSeen: number; // 最近一次 WallTime 锚点（epoch ms）
}
```

* **SimulationTime**：唯一驱动模拟的时间。所有生长、水分、事件、季节判断只读它。
* **WallTime**（`Date.now()`）：只允许出现在两处——启动时计算增量、渲染 / UI 层做动画插值。模拟代码中出现 `Date.now()` 属于违例（ESLint no-restricted-syntax 强制）。

### 1.2 推进规则

```text
wallDelta = wallNow() - lastWallSeen

wallDelta < 0   → 时钟回拨：保护模式（见 1.4）
wallDelta ≥ 0   → 目标 = floorToGrid(wallNow)（见 1.3）
                  simTime 以整步推进逼近目标，不足一步的余量留在网格外自然累积
                  然后 lastWallSeen = wallNow()
```

* 会话内：低频定时器（每 30～60 秒真实时间）+ 唤醒事件触发增量推进
* 启动 / 唤醒：走同一条批量管线做 catch-up——"在线"与"离线"只是 delta 大小不同
* 大缺口（数周 / 数月）不做总量截断：总方案 §42 要求植物按真实时间生长；但**执行必须分片**（见 1.3），必要时给出"补算中"提示

### 1.3 固定步长、网格锚定与输入结算

```ts
const SIM_STEP_MS = 3_600_000; // 1 逻辑步 = 1 模拟小时
```

**网格锚定（确定性关键）**：

* 步网格锚定在 simTime 轴原点：第 k 步永远覆盖 `[k·Δ, (k+1)·Δ)`，**与启动时刻无关**
* **不变量：simTime 永远落在网格上**——模拟只整步推进；会话内不足一步的余量是 `wallNow − simTime` 的可推导值，不落盘、不存状态，跨过边界时自然结算
* 植物在步中间出生，从下一个步边界加入；多实体共享同一张网格
* 由此：连续推进、分片推进、从种子重放三者的步序列逐字节一致（S2 内核验证的回归对象，见 05 §3）

**输入结算**：

* 玩家输入统一在**其 simTime 之后的下一个步边界**生效（如 10:37 浇水，在 11:00 步头结算）
* 界面上的即时反馈（水珠、动画）由渲染层做过渡表现，不改模拟状态
* 输入日志按原始 simTime 持久化，重放时按同一规则结算

其余规则：

* catch-up 循环按整步推进：`while (simTime < gridTarget) step(SIM_STEP_MS)`
* **时间预算分片**：单帧 ~16ms 的时间预算由宿主换算为**步数上限**传入 `advance(target, maxSteps)`（sim 内零计时 API，见 07 §3），超出则让出主线程下一帧继续；启动永不因补算卡死
* 事件密集期（开花等）允许在步内做子步细分，但对外仍是一个逻辑步

### 1.4 时间异常保护（R4）

| 异常 | 处理 |
| --- | --- |
| 时钟回拨（wallDelta < 0） | simTime 冻结；记录 `clock.anomaly.rollback` 事件；lastWallSeen 重锚为当前 WallTime；连续若干天正常前进后自动解除观察 |
| 休眠 / 唤醒 | powerMonitor `suspend / resume`；唤醒后按 1.2 走正常增量 |
| 时区 / 夏令时 | 以环境配置进入模拟（见 §2.2）：utcOffset 与半球记入存档，变更写成输入事件；simTime 仍是绝对时间轴 |
| 手动改系统时间大幅前跳 | 合法（视作真实经过），catch-up 走分片；> 30 天的缺口触发 Recap UX（P1） |

不做 DRM 式反作弊：改时间最多加速植物，不影响付费与成就公平性（成就由事件驱动，事件由模拟驱动）。

### 1.5 开发时间缩放

`timeScale ∈ {1, 10, 100, 1000}` 与 `advance(duration)` 只由 Simulation Console 调用（03 §3）。生产构建 timeScale 恒为 1，advance 入口不打包。加速只改变 simTime 推进速率，**不注入任何输入事件**，因此重放（R13）天然兼容。

## 2. 批量模拟管线

### 2.1 顶层签名

```ts
// sim/ 下唯一入口。输入世界状态 + 输入序列 + 步长，推进状态并产出事件。
function simulateStep(world: WorldState, dtMs: number, ctx: SimContext): void;
// ctx = { rng: RngStreams, sink: EventSink, inputs: InputTimeline }
```

单步内部顺序（固定，不可重排）：

```text
1. 采样环境（光照曲线 / 温度 / 季节 → 本步环境值）
2. 结算玩家输入（InputTimeline 中落在本步内的动作：浇水、移动摆放、换盆…）
3. 更新水分动态（蒸发 / 吸收 → plant.water）
4. 更新应激累积器（StressHistory，带衰减）
5. 生长结算（叶生命周期推进、株型参数、季节系数）
6. 事件检查（带事件预算与冷却，见 2.4）
7. simTime += dt
```

### 2.2 环境与输入

* **环境**：MVP 中环境是 simTime + 环境配置（EnvConfig）的确定函数（光照日曲线、季节曲线）。不依赖天气 API（总方案 §44）。
* **EnvConfig 必须收拢一切"本地性"参数，否则破坏确定性**：摆放位（窗边 / 桌中央 / 台灯下 / 阴影，总方案 §45）、**utcOffset**（光照日曲线靠它把绝对时间换算成本地时刻）、**半球**（南北半球季节相反，直接影响春秋型的休眠判断）。时区、夏令时与半球都不是"仅影响呈现"——它们以配置进入模拟，变更写成输入事件（`env.utcOffsetChanged` / `env.hemisphereChanged`），变化本身进入时间线。
* **玩家输入**：一切影响模拟的操作都以 `InputEvent { simTime, type, payload }` 落入 InputTimeline 并持久化。浇水不是"把 water 设为 0.9"，而是产生一个水分注入过程。输入在下一个步边界结算（§1.3）。输入日志同时是重放（R13）的数据源。

### 2.3 事件流（R12 地基）

```ts
interface SimEvent {
  seq: number;               // 全局单调序号
  simTime: number;
  plantId: string;
  kind: EventKind;           // 'firstLeaf' | 'wrinkle' | 'colorShift' | 'clock.anomaly' | ...
  tier: 'micro' | 'growth' | 'major';
  signalStrength?: number;   // 0~1，R5
  payload?: JsonObject;
}
```

事件是**唯一的事实记录**：履历（总方案 §28）、Growth Recap、Console 时间轴、发现率统计、未来成就，全部消费同一条事件流。事件在模拟中产生，立即追加落盘，与存档解耦。

### 2.4 事件预算（R7）

事件检查器内建三层冷却与配额（具体数值在 04 §8 定义）：

```text
micro : 每模拟日 ≤ N 次
growth: 同类事件冷却 ≥ C 天；并行酝酿事件 ≤ M 个
major : 同株并行 ≤ 1；同类间隔 ≥ 数周（模拟日）
```

超预算 → 排队或静默丢弃（丢弃也记一条 debug 级日志）。**禁止裸 `random()` 轮询**：概率检查只允许发生在"条件满足"之后（总方案 §2.3"有因果的未知性"）。

## 3. 状态与数据模型

### 3.1 世界状态

```ts
interface WorldState {
  formatVersion: number;
  simulationVersion: number;
  simTime: number;
  env: EnvConfig;            // 摆放位、亮度修正等
  plants: PlantState[];      // 单窗口多实体（§5）；MVP 恒 1 株
}
```

### 3.2 植物状态（示意，字段随 04 细化）

```ts
interface PlantState {
  id: string;
  speciesId: 'echeveria';
  seed: string;              // 64bit 随机数（序列化用字符串），创建时由 CSPRNG 生成
  genome: Genome;
  bornSimTime: number;

  water: number;             // 0~1 植株级水分；叶片 turgor 由其派生
  stress: { light: number; drought: number; temp: number }; // 累积器，带衰减
  stretch: number;           // 徒长程度 0~1
  seasonPhase: number;

  leaves: LeafState[];       // 按出生序排列（数组，保证确定性遍历）
  stems: StemState[];        // MVP：短茎桩
  counters: CounterMap;      // "首次类"事件的判定依据
}

interface LeafState {
  bornSimTime: number;
  ringIndex: number;         // 叶序环
  maturity: number;          // 0~1
  turgor: number;            // 0~1 饱满度
  colorState: number;        // 应激色量 0~1
  damage: number;            // 晒伤 / 疤痕 mask（M4+）
  droppedSimTime?: number;   // 脱落后保留为履历痕迹
}
```

### 3.3 Phenotype 派生（模拟 → 渲染的唯一桥梁）

```text
derivePhenotype(PlantState, simTime, generatorVersion) → PhenotypeSnapshot
```

* 纯函数，位于 `sim/phenotype/`，输出**参数**而不是网格：每叶 OrganPose（植物学语义姿态：倾角 / 方位 / 垂头 / 卷曲 / 生长进度等，定义见 07 §3）、尺寸、turgor、colorState、伤害 mask + 全局材质参数
* 渲染层（`render/`）只消费 Snapshot；生长动画 = Snapshot 之间插值 + shader 权重；渲染器永远不反推植物状态（总方案 §49）
* Snapshot 结构由 generatorVersion 钉扎，同样禁止隐式变更

### 3.4 确定性规则（I1）

* 随机数：种子化 PRNG（sfc32 一类），按用途分命名流（`rng.genome` / `rng.event` / `rng.decay`），流由 plant seed 派生
* 禁止 `Math.random()`；禁止遍历对象键做逻辑（用数组与稳定排序）
* Electron = 单一 V8 引擎，`Math.sin` 等在本产品生命周期内视为引擎内一致；跨引擎 / 跨设备分享（P2，种子码）再评估定点数
* 一切"今天发生了什么"的分支必须是状态的纯函数——重放时逐字节可复现

## 4. 渲染三态状态机（R1）

```text
            指针进入 / 拖动 / 菜单 / 大事件
   ┌──────────────────────────────────────┐
   │                                      ▼
Deep Idle ──(定时唤醒:短动画)──► Ambient ──► Active
   ▲                              │            │
   └────(动画结束且无变化)─────────┴────────────┘
```

| 状态 | 渲染 | 典型触发 | 退出 |
| --- | --- | --- | --- |
| Deep Idle | RAF 停止，0 帧 | 无任何视觉变化（绝大多数时间） | 定时器唤醒 / 指针进入 / 系统事件 |
| Ambient | 按需渲染：每 3～10 秒（抖动）触发 0.5～2 秒短动画（微风 / 呼吸 / 光斑），播完停帧；期间 sim 步照常低频推进 | 常驻生命感 | 动画结束 → Idle；交互 → Active |
| Active | 连续 RAF，目标 60 FPS（集成显卡吃紧降 30） | 指针在窗口内、拖动、菜单、事件回放 | 空闲超时 / 指针离开 |

补充规则：

* 任何可见状态变化（新叶、变色跨档）⇒ 至少强制渲染 1 帧（Deep Idle 也会醒）
* 前台全屏应用检测 / 窗口最小化 / 屏幕关闭 ⇒ 强制 Deep Idle（连 1 帧心跳都没有）
* sim 步推进与渲染完全解耦：Idle 时模拟照常（定时器驱动），只是不画

## 5. 单窗口多实体（R6）

```text
BrowserWindow（透明 / 无边框 / 置顶）×1
  └─ Three.js Renderer ×1
       └─ Scene
            ├─ PlantEntity（母株）
            │    ├─ PlantGroup（叶网格 / 茎）
            │    └─ PotGroup（盆 + 土）
            ├─ PlantEntity（子株 / 未来多株…）
            └─ Effects
```

* **PlantEntity** = { id, stateRef, rootTransform, slotId }；子株 = 新实体，与母株同 Scene
* **Plant Slot**：桌面上可占用位置的抽象。首发 1 个 Slot，但 SlotRegistry 从第一天存在；未来"桌面 Shelf"只是 Slot 排布策略
* **拖动** = 移动实体 rootTransform（Active 态）；**滚轮缩放** = 相机 / 全局 scale；窗口本身尽量少动（窗口尺寸策略——固定大窗 vs 随内容收缩——由 M0 的穿透验证结果决定）
* **PointerHitResolver**（总方案 §35）：输入屏幕坐标，输出 `Ignore | Hover | Interact | Drag | Menu`；实体命中用不可见代理网格 raycast，无命中 ⇒ `setIgnoreMouseEvents(true, { forward: true })`，指针移动时动态切换。窗口穿透逻辑与游戏交互逻辑分离，中间只经它一手

## 6. 存档与版本迁移

### 6.1 存档内容

```ts
interface SaveFile {
  formatVersion: number;
  simulationVersion: number;
  speciesVersion: number;
  generatorVersion: number;

  simTime: number;
  lastWallSeen: number;

  world: WorldState;
  inputLogRef: string;         // 输入 WAL 文件指针（inputs 移出存档，见 6.4）
  eventLogRef: string;         // 事件日志文件指针

  appState: { windowBounds, scale, settings };
}
```

* **不存**：几何缓冲、纹理、渲染状态、任何派生表现（I5）——载入 = 存档 → Simulation → Phenotype → Geometry（总方案 §51）
* 事件日志单独追加文件（JSONL），按大小 / 时间轮转：近 90 天全量 + 更早的 major / growth 摘要
* 输入日志（WAL）单独追加文件，保留全量——重放（R13）依赖从出生起的完整输入序列；浇水类事件极小，多年也在 MB 量级

### 6.2 写入策略

```text
时机：启动 catch-up 完成后 / 每 6 模拟小时 / 退出时 / 重要事件后
方式：写临时文件 + 原子 rename；保留 save-1 / save-2 双代 + backup 环形 5 份
校验：载入时 schema 校验，损坏则回退上一代并提示
```

### 6.3 版本迁移（I6）

* `migrations: Map<fromVer, (save) => save>` 显式注册；无迁移路径的旧版本存档 → 拒绝升级、按旧规则继续（保留旧模拟代码路径）或明确弹窗征询
* 行为性修改必须 bump simulationVersion；**禁止**"顺手改了公式导致老植物变形"（总方案 §33）
* 迁移函数必须携带单测：旧样本存档 → 迁移 → 事件流不回退、不重复

### 6.4 崩溃一致性（输入 WAL）

存档是检查点，事件日志是即时追加的——崩溃时两者必然不一致：日志里有检查点之后的事件，而检查点之后的输入可能还只在内存里。因此：

* **输入日志（WAL）即时追加**：玩家输入产生后先落 WAL 再进内存；检查点记录 WAL 偏移
* **载入流程**：

```text
1. 载入最近的合法检查点（simTime = S）
2. 事件日志截断到 S（之后的部分作废）
3. 用输入 WAL 中 S 之后的输入重放模拟至崩溃前
4. 重写事件日志尾部
```

* 第 4 步之所以安全：I1 确定性保证重放生成的事件与崩溃前已写入的**逐字节相同**——"截断重写"与"校验保留"等价，实现选简单者
* 效果：崩溃最多丢一条"尚未结算"的输入，绝不丢已结算的输入，绝不产生重复事件（不会出现两条"第一片新叶"）

## 7. 性能预算

| 指标 | 目标 |
| --- | --- |
| Deep Idle CPU / GPU | ≈ 0（无 RAF；定时器空转忽略不计） |
| Ambient 平均 CPU | < 2%（按需短动画） |
| Active | 60 FPS @ 集成显卡；CPU < 8% |
| 启动到可见 | < 2 s（含大缺口 catch-up 的首帧） |

| 存档大小 | < 1 MB（事件日志除外） |
