## 0. 先读：四个永不混淆的概念

| 概念 | 是什么 | 给谁 |
| --- | --- | --- |
| `PlantState` | 模拟内部真相（水分 / 应激 / 叶生命周期） | 模拟自身、存档 |
| `PhenotypeSnapshot` | 当前表现的参数快照（OrganPose + 材质参数） | 渲染层**只读** |
| `SaveFile` | 磁盘持久化数据（状态 + 时间 + 版本 + 引用） | 持久化服务 |
| `SimEvent` | 事实记录 | 事件日志、履历、Console、未来成就 |

渲染层永远不反推 PlantState；存档永远不含几何。

## 1. 仓库结构：三层 + workspace 强制隔离

```text
repo/
  packages/
    sim/            # 纯 TS 模拟内核：零 runtime 依赖（无 DOM / Node / three / electron）
    render/         # three.js：渲染与渲染调度（只 import type 读 sim 的快照类型）
  apps/
    desktop/
      src/
        main/       # Electron 主进程
        preload/    # contextBridge 类型化 IPC
        renderer/   # 组合根：把 sim、render、UI、输入接起来
        dev/        # Simulation Console（仅 DEV 构建）
  docs/             # 01～07 规格（总方案在仓库根目录）
  ARCHITECTURE.md   # AI 契约卡（一页）
```

依赖方向（单向，CI 强制）：

```text
sim      ← 无人依赖（最底层）
render   → sim 的类型（import type）
desktop  → sim + render

sim    ↛ render / electron / DOM / Node   ❌
render ↛ electron / main                  ❌
```

三道硬门禁：

1. `sim` 的 tsconfig：`lib: ["ES2022"]` + `types: []` —— 误用 DOM / Node API 直接编译报错
2. `sim` 的 package.json：运行时依赖白名单为空
3. CI import-graph 检查（eslint-plugin-boundaries 或等价）：跨包非法 import 直接打死

工具链只用 pnpm workspaces，不上 monorepo 构建编排；打包时 Vite 把包全部 bundle，拆包只是开发期约束。

## 2. 运行时拓扑

```text
main 进程（OS 与文件）              renderer 进程
 ├ WindowController                ├ SimHost（端口，实现可换）
 ├ TrayController                  ├ RenderScheduler ──► PlantRenderer
 ├ PowerMonitor                    ├ PointerHitResolver（输入 → InputEvent）
 ├ FullscreenWatcher               ├ UI（右键菜单 / 检视）
 ├ PersistenceService（唯一文件 IO） ├ UI 消费的 host 缓存快照
 └ SteamAdapter（先空实现）          └ dev Console（DEV）
          ▲──── IPC（类型化注册表）────▲
```

* **SimHost 是端口，不是实现**：第一版 `InProcessSimHost` 跑在渲染进程；将来 `WorkerSimHost` 只换传输。为使这成立：
  * **命令异步**：`advance` / `apply` 走消息语义（进程内实现为立即完成）
  * **快照缓存读**：renderer 每帧读 host 缓存的最新 `PhenotypeSnapshot`（同步、无 Promise）；Worker 模式下由 worker 推送覆盖缓存——渲染代码两种模式下零改动
* R2 批量结算的红利：模拟不依赖精确定时器，窗口被遮挡 / 定时器降频都无害，唤醒后按真实时间差补算
* **文件 IO 只在主进程**：sim 产出"要保存的数据"，经 IPC 交 PersistenceService 原子写入；sim 不碰文件系统，测试无需 mock
* OS 信号（电源 / 全屏）统一转成渲染调度与模拟可消费的少数事件

## 3. `sim` 包

```text
sim/src/
  clock/       SimClock：单调 simTime、回拨保护（02 §1）
  rng/         sfc32 命名随机流（genome / event / decay，02 §3.4）
  world/       WorldState、PlantState、Genome、InputEvent、EnvConfig 类型
  env/         环境曲线 + calendar：simTime + EnvConfig → 光照 / 季节 / 昼夜相位（02 §2.2）
  engine/      SimEngine：推进、输入队列、快照缓存、序列化
  step/        simulateStep：固定顺序单步结算（02 §2.1）
  events/      事件流 + 事件预算（02 §2.3 / 2.4）；生命周期状态机属 M4（04 §12），不提前建
  species/     每原型一个目录，实现 SpeciesDef；M1～M5 只有 echeveria/（R10）
  phenotype/   derivePhenotype：状态 → OrganPose 快照（02 §3.3）
  persist/     存档 schema、迁移注册表、输入 WAL、序列化（02 §6，纯函数）
```

核心接口（示意）：

```ts
interface SimEngine {
  readonly simTime: number;                    // 永远落在步网格上（02 §1.3）
  advance(targetSimTime: number, maxSteps: number): { done: boolean };
    // target 由引擎内部 floorToGrid；预算用步数而非 ms——sim 零计时 API
  apply(input: InputEvent): void;              // 只入队；下一个步边界结算（02 §1.3）
  latestSnapshot(): PhenotypeSnapshot;         // 渲染层唯一数据来源（缓存语义）
  checkpoint(): SaveFile;                      // 检查点，不含几何
}

// 每个原型实现此接口；引擎不认识 Echeveria。
// 纪律：接口从 echeveria 具体实现中提取（M1），不预先镀金。
interface SpeciesDef {
  id: string;
  version: number;                             // = speciesVersion
  createGenome(rng: Rng): Genome;
  growStep(plant: PlantState, env: EnvSample, dt: number, ctx: StepCtx): void;
  morphology(plant: PlantState): OrganPose[];  // 生长语法：植物学语义姿态，非引擎 Transform
}

interface OrganPose {
  // 倾角 / 方位角 / 垂头 / 卷曲 / 中心偏移 / 生长进度 / ring / 尺寸 …（render-neutral，02 §3.3）
}
```

确定性纪律：随机只走命名流，跨系统互不影响；"事件级派生 seed"（plantSeed + kind + seq）作为 M4 设计点记入 04，不提前实现。

## 4. `render` 包

```text
render/src/
  scheduler/   RenderScheduler：三态状态机（02 §4），**唯一决定"何时画"**
  scene/       SceneRoot：场景、相机、光照
  plant/       PlantRenderer：消费 PhenotypeSnapshot，更新网格与 shader 参数
  geometry/    叶 / 盆 / 土参数化几何：纯函数（参数 → 顶点数据），可脱离场景批量出图
  materials/   MaterialSystem
  effects/     微风、露珠、光斑
```

规则：

* 渲染层不反推植物状态，只读快照；生长动画 = 快照间插值 + shader 权重
* Ambient = 按需渲染 + 每 3～10 秒短动画、播完停帧（R1 定稿，**不是持续低帧率**）
* 所有模块禁止私自 requestAnimationFrame——画的时机只归 RenderScheduler
* `geometry/` 的纯函数性是 03 §7 批量联系表与审美验收的前提

## 5. `apps/desktop`

```text
src/main/      window/  tray/  power/  fullscreen/  persistence/  steam/
src/preload/   ipc/（类型化注册表，main 与 preload 共用同一份类型）
src/renderer/  composition/（组合根）  input/  ui/  host/（SimHost 装配）
src/dev/       simulation-console/（03；动态 import，仅 DEV）
```

* **PointerHitResolver**：输入屏幕坐标，输出 `Ignore | Hover | Interact | Drag | Menu`；窗口穿透只在这里切换（02 §5）
* 拖动 = IPC 手动移动窗口；禁用 `-webkit-app-region: drag`（05 A4）
* 全屏检测、电源等 OS 信号归 main，转成少量事件上行

## 6. 工程护栏

* lint：sim 禁 `Math.random` / `performance`；**Date 精细规则**——禁止读取当前时间（`Date.now` / `new Date()`），纯函数 timestamp → 日历换算允许
* 依赖三道门禁（§1）
* dev 隔离：Console 动态 import + 发布构建 grep 验证（03 §2 / §12）
* 测试：Vitest；sim 第一批测试 = S2 清单（05 §3），长期作为回归第一条

## 7. 第一个垂直切片

```text
SimClock → 1 片叶子生长（simulateStep）
        → PhenotypeSnapshot → PlantRenderer 画出
        → PersistenceService 存档 → 重启 catch-up → replay
```

* S2 的确定性测试内含其中（05 §3）
* **先在普通窗口跑通，再套透明壳**——窗口问题不阻塞内核验证
* 这条线通过 = sim / render / desktop 三层全部接缝被真实验证；此后所有里程碑都是在这条线上加内容
