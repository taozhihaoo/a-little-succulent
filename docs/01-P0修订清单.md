## 2. 修订详情

### R1 渲染三态状态机

**问题**：总方案 §47 要求"无变化时停止持续渲染"，但 §37 与微观惊喜系统（§7.1）要求微风、呼吸、光斑持续存在——二者直接冲突，实现时必然二选一或各自妥协。

**决策**：不做二选一，建立三级运行状态：

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| Deep Idle | 无可感知视觉变化 | 不渲染、不运行动画，只保留时间 / 事件模拟（绝大多数时间） |
| Ambient | 常驻生命感 | **按需渲染**：每 3～10 秒触发一段 0.5～2 秒短动画（微风 / 呼吸 / 光斑），播完停帧 |
| Active | 指针进入 / 拖动 / 菜单 / 大事件播放 | 连续渲染 30～60 FPS |

关键细化：Ambient 不采用"持续 5～15 FPS"，而是**按需渲染 + 周期性短动画**，比持续低帧率更省。任何可见状态变化（新叶、变色跨档）至少强制渲染 1 帧。

### R2 批量模拟

**问题**：总方案 §12.1 已暗示"昨天的植物 + 时间 = 今天的植物"，但从未明文禁止逐秒 tick。默认写法（每秒 `plant.update()` 累积）会直接杀死离线结算、时间加速、重放与版本迁移。

**决策**：写回架构纪律——

```text
禁止：每秒调用 plant.update() 逐步累积
必须：simulate(lastSimTime, currentTime) 批量结算
```

植物不是靠真实经过每一秒才活着，而是打开时直接计算过去发生了什么。这是 R3 / R4 / R13 的共同地基。完整管线见 02。

### R3 统一时间源

**决策**：全项目唯一时间源 SimulationClock。`SimulationTime`（单调虚拟时间，唯一驱动模拟）+ `WallTime`（系统真实时间，只用于推进 SimulationTime）。模拟代码内禁止 `Date.now()`（lint 级强制）。开发模式提供 ×1～×1000 加速与跳转。

### R4 时间异常保护

**决策**：检测到系统时钟回拨（`WallTime < lastSeen`）时，SimulationTime 冻结并记录异常事件，植物绝不倒流；休眠 / 唤醒、时区与夏令时变化不直接进入模拟，只作为时间增量处理。不做 DRM 式反作弊。

### R5 迹象可感知性

**问题**：迹象一定是在编辑器放大状态下设计的，但玩家桌面上植物通常只有 120～180 px（最小 80～100 px）。"设计上变了、视觉上没变"意味着期待系统死亡。

**决策**：

* 每个迹象必须通过**实际桌面尺寸可感知测试**（100 px 下可辨认）
* 引入 SignalStrength 0→1，随生命周期自然爬升（0.1 极弱 → 0.9 无法忽略），与"潜伏 → 迹象 → 酝酿"逐段对应
* Simulation Console 提供多尺寸同步预览工具（见 03 §8）

### R6 单窗口多实体

**问题**：子株、群生、多株出现后"住在哪里"是架构决策，必须现在定，否则将来被迫多窗口。

**决策**：**整个产品只有一个桌面窗口**：一个 Three.js Scene、多个 PlantEntity；子株是实体不是窗口。位置抽象为 Plant Slot，首发 1 个 Slot、架构按多 Slot 设计。禁止为单株植物创建独立窗口。

### R7 事件预算

**问题**：微 / 成长 / 大事件三层已定义（总方案 §7），但没有频率上限。AI 实现极易写成"每 30 秒 random 一次"，植物变成"一直在发生事情"，期待感归零。

**决策**：三类事件全部带频率预算（数值在 04 §8 定义），超限排队或丢弃；禁止裸 random 轮询触发——概率检查只允许发生在"条件满足"之后。

### R8 美丽失败

**问题**：总方案 §2.4 / §2.5 在哲学层面说了"失去不等于失败"，但没有验收门槛。"缺水 = 变丑"一旦发生，玩家会认为"我养坏了"，产品退回传统养成游戏。

**决策**：缺水、徒长、晒伤、老化、掉叶、休眠全部纳入视觉审核：**异常状态也必须好看，只是美的方向不同**。

### R9 现实 / 抽象边界

**决策**：明确"以真实植物现象为灵感，不追求植物学意义上的精确模拟"。每个机制归入 Realistic / Simplified / Stylized 三档，杜绝"这到底科不科学"的无限争论。

### R10 单原型锁定

**问题**：§54"首发 3～5 个原型"是发布目标；里程碑若不显式锁定，开发会被"多原型"摊薄。

**决策**：M1～M5 全部里程碑只用莲座型（Echeveria 类）一个原型；首发数量在 M5 后按 Store 页需要决定。

### R11 Desktop Mode Time-box

**决策**：M0 只验证 Floating Mode；Desktop Mode 技术验证限时（≤ 2 个工作日），超时搁置。植物模拟 + 期待系统 + 材质才是产品；Desktop Mode 是体验增强，不是成立条件。

### R12 履历分层

**决策**：事件日志基础设施属于 P0（第一天起落盘，是履历、Growth Recap、发现率统计与未来成就的共同地基）；完整履历时间线 UI（Journal）属于 P1 / M5。

### R13 重放实现

**决策**：不做真回退（逐帧倒退需要存全量状态）。利用确定性（总方案 §50）：`seek(day N)` = 从种子重放输入日志到目标日 + 每 7 模拟日一个状态检查点加速。暂停 / 播放 / 逐段前进的"过程感"验证完整保留。

### R14 唯一性检测后置

**决策**：第一轮不做图像特征提取。M5 用 Phenotype 数值指标（叶数、高宽比、紧凑度、色相分布）做近邻重复检测，工具入口放在 Simulation Console。

### R15 发现率遥测

**决策**：从第一天起事件落盘（R12 免费带来），`Triggered / Visible / Discovered` 计数器在 Console 展示；仅本地 JSONL，无网络上传。

## 4. 未决问题（不阻塞开工）

* 环境历史的压缩与保留策略（细节保留时长）
* 多显示器跨屏拖动行为
