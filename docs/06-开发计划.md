## 2. 各阶段要点（只记规格没说的执行顺序）

**M0**：按 05 执行。S2（模拟内核验证）与 Electron 主线**同时开工**，不占 8 工作日时间盒；S2 通过是进入 M1 的前置。Electron 若失败的降级链见 05 §7。

**M1～M2**：先叶片曲面 + 莲座排布，再上 100 株联系表（总方案 §41.4 的自动化在 03 §7）。材质是独立阶段，决定成败，不与形态混赶。

**M3**：按 02 实现即可——02 的三个缺口（网格锚定 / 时区与半球配置 / 输入 WAL）已于 2026-09-30 修订进规格，不存在"先修规格"这一步。Console 的时间控制随内核同期搭建（03 §3 与 02 §1 共用入口）。

**M4～M5**：固定节拍——每加一个事件：Console ×100 加速走一遍全程 → 100 px 缩略图验证迹象可辨（03 §8）→ 上线后按发现率日志（03 §10）回调 SignalStrength 与预算。

## 3. 贯穿全程的三条实践

1. **从 M3 起，一株植物在开发者主机常驻运行。** 7 天 / 30 天验收无法加速，越早开始越好；它同时是最真实的性能与体验测试。
2. **三个判断点必须诚实执行**：M0（引擎去留）、M2（够不够好看）、M3（愿不愿意天天开着）。任何一关不过，先解决它，而不是继续堆功能。
3. **M2 之后立即开 Steam"即将推出"页。** M1 / M2 产出的截图与延时摄影就是首批商店素材；"即将推出"最短展示期与审核时长以 Steamworks 官方文档为准，届时确认。

## 4. 第一周清单

0. 先读《[07 代码架构](./07-代码架构.md)》与根目录 ARCHITECTURE.md（AI 契约卡）
1. 建仓库：Electron + Vite + TypeScript(strict)，`packages/sim | packages/render | apps/desktop` 三层（07 §1）
2. 三道硬门禁：sim 包 types:[]、运行时依赖白名单、CI import graph；类型化 IPC 注册表（07 §6）
3. 透明无边框窗口 + 置顶 + 占位立方体（A1 / A2，含 alpha 边缘检查）
4. 鼠标穿透：PointerHitResolver 判定，动态切换 `setIgnoreMouseEvents`（A3）
5. 托盘 + IPC 手动拖动（A4 / A6），记录第一版空闲 CPU / GPU / 内存

并行：S2 模拟内核（05 §3）——垂直切片先在普通窗口跑通，再套透明壳（07 §7）。
第 5 步得到的数字，是后续所有性能决策的基线（02 §7）。
